# 参数账：63.9M 是怎么加出来的

## 1. 唯一的规则

模型里「学到」的东西全是权重表，表的形状是 `[行, 列]`，**参数个数 = 行 × 列**。

```text
nn.Linear(768, 768, bias=False)   →  768 × 768 = 589,824 个参数
```

两条推论：

- 参数跟 batch、跟序列长度**无关**。喂 1 句话和 100 句话，表一样大。
- `nn.Linear(in, out)` 永远是 `in × out` 个；MiniMind 里所有投影都 `bias=False`（无偏置），所以不用额外加。

## 2. 缩小 100 倍先算一遍

词表 10、维度 8、2 个 Q 头、每头 4 维、1 组 KV（即 2 个 Q 头共享 1 组 KV）、FFN 中间维 16、1 层：

| 部件 | 形状 | 参数 |
|---|---|---|
| embedding | 10 × 8 | 80 |
| q_proj | 8 × 8 | 64 |
| k_proj | 8 × 4 | 32 |
| v_proj | 8 × 4 | 32 |
| o_proj | 8 × 8 | 64 |
| q_norm + k_norm | 4 + 4 | 8 |
| gate_proj + up_proj | 16 × 8 ×2 | 256 |
| down_proj | 8 × 16 | 128 |
| 两个 RMSNorm | 8 × 2 | 16 |
| 末尾 RMSNorm | 8 | 8 |
| **合计** | | **688** |

这份账和 64M 那份**完全同构**，只是把 10 换成 6400、8 换成 768、16 换成 2432、1 层换成 8 层。

## 3. 真实的一层（hidden=768）

**Attention 子层 → 1,769,664**

| 部件 | 计算 | 参数 |
|---|---|---|
| q_proj | 768 × 768 | 589,824 |
| k_proj | 768 × 384 | 294,912 |
| v_proj | 768 × 384 | 294,912 |
| o_proj | 768 × 768 | 589,824 |
| q_norm | 96 | 96 |
| k_norm | 96 | 96 |

> 为什么 k/v 是 384：`kv_heads(4) × head_dim(96) = 384`，而 `heads(8) × 96 = 768`。

**FFN 子层 → 5,603,328**

| 部件 | 计算 | 参数 |
|---|---|---|
| gate_proj | 2432 × 768 | 1,867,776 |
| up_proj | 2432 × 768 | 1,867,776 |
| down_proj | 768 × 2432 | 1,867,776 |

**两个 RMSNorm → 1,536**（`input_layernorm` 768 + `post_attention_layernorm` 768）

**一层合计 = 1,769,664 + 5,603,328 + 1,536 = 7,374,528**

## 4. 整体三步

| 部位 | 计算 | 参数 |
|---|---|---|
| ① 词表 | 6400 × 768 | 4,915,200 |
| ② 8 层 | 7,374,528 × 8 | 58,996,224 |
| ③ 末尾 RMSNorm | 768 | 768 |
| **总计** | | **63,912,192 ≈ 63.9M** |

闭式：

$$
N = \underbrace{V d}_{\text{词表}} + \underbrace{L\left(3d^2 + 3dm + 2d_h + 2d\right)}_{\text{每层}} + \underbrace{d}_{\text{末尾 norm}}
$$

$d=768,\ m=2432,\ L=8,\ V=6400,\ d_h=96$ 代入即得上表。

实测核对：`MiniMindForCausalLM(768, 8)` 的 `sum(p.numel())` = **63,912,192**，一致。

## 5. 几个常见疑惑

**Q：8 个头为什么不多乘 8？**
每个头是 768→96，8 个头合起来 $8\times768\times96 = 589{,}824$，正好等于 $768\times768$。**分头只是把同一张表切开用，不增加参数**；增加的只有计算（8 个独立小注意力）和表达能力。

**Q：GQA 到底省了多少？**
如果 K/V 也做 8 头，k_proj/v_proj 就是 768×768，一层多出 $2\times(589{,}824-294{,}912)=589{,}824$ 个参数，8 层就是 **4.7M**。GQA 省下的主要是这 4.7M 参数，加上推理时 KV cache 直接减半。

**Q：为什么不共享 embedding 就会多 4.9M？**
`lm_head` 是一张 6400×768 的表（4,915,200 个参数）。`tie_word_embeddings=True` 时它直接用 `embed_tokens` 的同一块权重，等于白拿一层输出头。

**Q：FFN 的 2432 是哪来的？**
`ceil(768 × π / 64) × 64 = 2432`。经典 Transformer 是 $4d=3072$，LLaMA 系用 SwiGLU（三个矩阵而非两个）后要把宽度压到约 $\frac{8}{3}d = 2048$ 才等参数量；2432 比 2048 多花约 19% 参数，换来更好的效果。

**Q：MoE 版本呢？**
把单个 FFN 换成 N 个专家 FFN + 一个 router，token 只走 top-k 个专家。**总参数按专家数涨，但每个 token 只激活一小部分**，所以显存吃得多、算力花得少。
